## 1. Data Pipeline

### 1.1 Tokenizer — `data/tokenizer.py`

**Purpose:** Define the closed vocabulary for symbolic expressions and convert between formula strings, RPN token lists, and integer index sequences.

#### Vocabulary Design (44 tokens total)

```
Special (4):   <PAD>  <BOS>  <EOS>  <UNK>
Variables (9): x1 x2 x3 x4 x5 x6 x7 x8 x9
Constants (11):  0  1  2  3  pi  e  c1 c2 c3 c4 c5
Binary ops (4):  +  -  *  /
Unary ops (16):  sqrt sq exp log sin cos tan arcsin arccos arctan
                 cosh tanh sinh inv abs neg
```

**Why RPN?**
A formula like `sin(x1 + x2) * x3` becomes `x1 x2 + sin x3 *` in RPN. Two properties make RPN ideal here:
1. **No parentheses needed** — structure is entirely determined by operator arity
2. **Stack-checkable validity** — at every step, the valid next tokens are fully determined by the current stack depth. A binary op (`+`, `*`) requires depth ≥ 2; a unary op requires depth ≥ 1; EOS is valid when depth == 1. Any other constraint can be checked in O(1).

**Why closed vocabulary?**
Physics formulas from the AI Feynman dataset use a finite set of operations. Unknown tokens never occur in practice. `UNK` exists for safety but is never actually emitted.

**Why `c1`...`c5` placeholder constants?**
Arbitrary numerical constants (e.g. `9.81`, `1.38e-23`) cannot be generated by a fixed vocabulary. Instead, the model generates a placeholder (`c1`, `c2`, ...) and BFGS post-processing fits the actual numerical value from data after generation. This cleanly separates *symbolic structure discovery* (the model's job) from *numerical constant optimization* (SciPy's job).

**Skeletonization for Deduplication:**
During inference, all constants (`c1`, `c2`, ...) and numeric literals are replaced with unique placeholders (`CONST0`, `CONST1`, `CONST_NUM0`, ...) to identify structurally identical candidates. This ensures BFGS optimization is only run once per unique mathematical structure.

**`MAX_SEQ_LEN = 50`**
The longest formula in the Feynman dataset is ~31 tokens in RPN. 50 gives a comfortable upper bound including BOS + EOS.

#### Key Functions

| Function | Description |
|---|---|
| `is_valid_rpn(tokens)` | O(n) stack-counter check. Returns True iff the token sequence produces exactly one complete expression. |
| `get_valid_next_tokens(depth, seq_len, max_len)` | Returns the list of valid token indices at the current generation step. Used as a hard validity mask during inference. Vectorized for batched generation. |
| `formula_string_to_rpn(formula_str, var_names)` | Converts a SymPy-parseable string (e.g. `"exp(-theta**2/2)/sqrt(2*pi)"`) to RPN tokens via postorder tree traversal. Variable names are mapped to `x1`, `x2`, etc. |
| `encode_formula(tokens, add_bos, add_eos, pad_to)` | Integer-encodes a token list, optionally adding BOS/EOS and padding to `MAX_SEQ_LEN`. |
| `decode_formula(indices, strip_special)` | Reverse: index list → token list. |
| `rpn_to_sympy(tokens)` | Evaluates an RPN token list using a stack to build a SymPy expression. Variables become `sympy.Symbol`s, constants become `sympy.Integer` or `sympy.pi`. |
| `skeletonize(token_ids)` | Converts RPN tokens to a SymPy skeleton string, replacing all constants with unique `CONST{i}` placeholders for deduplication. |

#### `_sympy_to_rpn` — Postorder Tree Traversal

This function recursively walks a SymPy expression tree and emits tokens in postorder (children before parent). Key decisions:

- **`Rational`** (e.g. `1/2`) is expanded as `[1, 2, /]` — avoids introducing a float
- **`Float`** (any non-integer numerical constant) is mapped to the next `c1`...`c5` placeholder. SymPy often produces `Float(0.5)` for `1/2` after simplification, so this fallback is important.
- **`Mul(-1, x)`** (negation) is special-cased to emit `[x, neg]` rather than `[-1, x, *]` — keeps the formula compact and more readable.
- **`Pow(x, 2)`** → `[x, sq]`, **`Pow(x, -1)`** → `[x, inv]`, **`Pow(x, Rational(1,2))`** → `[x, sqrt]` — common exponents get dedicated tokens to avoid multi-token representations.

### 1.2 Unit Table — `data/unit_table.py`

**Purpose:** Look up the SI unit vector for every named physical quantity that appears in the Feynman dataset.

#### 5-Dimensional Unit Space

Every physical quantity is represented as a vector of 5 integers: `[mass, length, time, current, temperature]` (SI base dimensions). Examples:

| Quantity | Units | Vector |
|---|---|---|
| Force | kg·m/s² | `[1, 1, -2, 0, 0]` |
| Velocity | m/s | `[0, 1, -1, 0, 0]` |
| Energy | kg·m²/s² | `[1, 2, -2, 0, 0]` |
| Dimensionless | — | `[0, 0, 0, 0, 0]` |

**Why integers?** Exponents in physics are always small integers (typically -4 to +4). This avoids floating-point issues in unit propagation and enables exact comparison.

#### Class Index Encoding

Integers in the range [-4, +4] are mapped to class indices 0–8 (offset by +4). Value 4 = index 4 = exponent 0 = dimensionless. This enables cross-entropy classification over unit dimensions.

#### `get_unit_matrix(var_names)` 

Takes a list of variable names (e.g. `['F', 'q1', 'r']`) and returns a `[n_vars, 5]` numpy array of unit vectors. Unknown variable names → dimensionless `[0,0,0,0,0]`.

### 1.3 Data Utilities — `data/utils.py`

#### IEEE-754 Bit Encoding — `to_ieee754_16bit(X)`

This is arguably the most important preprocessing decision in the project.

**Problem:** Standard normalisation (z-score, min-max) would destroy the symbolic content of the data. If `y = 2πr`, scaling `r` by `σ_r` changes the formula to `y = 2π·σ_r·r_normalised` — the model would learn a formula with a different constant.

**Solution:** Represent each float as its binary IEEE-754 half-precision (float16) bit pattern — a 16-bit sequence of `{0, 1}`. No normalisation. The bit representation carries:
- Sign bit (index 0)
- 5 exponent bits (indices 1-5)  
- 10 mantissa bits (indices 6-15)

The model sees the raw numerical information at the bit level, allowing it to learn patterns like "the sign bit alternates" or "the exponent stays constant" without any scale assumptions.

**Implementation:** `numpy.float16` → `uint16` view → `numpy.unpackbits` → `[N, n_vars, 16]` binary array.

#### `compute_unit_targets(rpn_tokens, var_names)`

For each token in an RPN sequence, computes what unit vector that token's subtree produces. Uses the same unit propagation rules as `propagate_units` in the synthetic dataset. This is the ground truth for the `UnitLoss`.

### 1.4 AIF Dataset — `data/aif_dataset.py`

**Purpose:** Load the AI Feynman (Udrescu & Tegmark 2019) dataset of 100 physics equations for evaluation and fine-tuning.

#### Design: Preprocessing Once, Subsampling at Training Time

Each equation has up to 100,000 data rows. Loading all 100k rows per batch would be prohibitive. Instead:

1. **First run:** Parse CSV, load data files, compute IEEE-754 encoding, tokenise formula, compute unit targets → save as `PreprocessedEquation` objects to a `.pt` cache file.
2. **Subsequent runs:** Load from cache in seconds.
3. **`__getitem__`:** Subsample 200 rows at random from the precomputed arrays. Different rows each epoch → acts as data augmentation.

**Why not cache 200 rows?** Because the subsampling is randomised and different rows give different gradient signals. Using a fixed subsample would reduce effective dataset size and hurt generalisation.

#### `collate_fn`

Standard torch stack for tensors, list collection for strings (`eq_id`, `formula_str`, `var_names`). Strings cannot be stacked into tensors but are needed for evaluation.

#### `build_aif_dataloader` — `num_workers` and `pin_memory`

```python
pin_memory=(num_workers > 0),
persistent_workers=(num_workers > 0),
```

`pin_memory` speeds up CPU→GPU transfer by pre-locking memory pages. It's meaningless (and causes warnings) when `num_workers=0` because there's no inter-process transfer. Setting it conditionally prevents confusion.

On Colab, `num_workers > 0` uses fork-based multiprocessing which is efficient. Set `num_workers=0` for local debugging if needed.

### 1.5 Synthetic Dataset — `data/synthetic_dataset.py`

**Purpose:** Generate an unlimited supply of physics-informed synthetic equations for pretraining. Unlike random mathematical expressions, these equations are dimensionally consistent — i.e., they could plausibly describe a real physical relationship.

#### Generation Pipeline

```
1. Sample n_vars from distribution matching Feynman dataset (1-9 vars, weighted)
2. Sample variable types from physics domain pools (mechanics, EM, thermodynamics, …)
3. Build expression tree top-down respecting unit consistency:
      At each interior node, sample operator and recurse.
      If no valid operator exists (unit mismatch), fall back to a leaf.
4. Convert tree → SymPy, simplify
5. Apply affine transformation: xᵢ → aᵢxᵢ + bᵢ (diversifies distribution)
6. Evaluate on sampled data, check for NaN/Inf/constant output
7. Add Gaussian noise (ε ∈ {0, 1e-4, 1e-3, 1e-2})
8. IEEE-754 encode, tokenise, compute unit targets
```

#### Unit Propagation — `propagate_units(operator, child_units)`

The heart of dimensional validity checking. Rules:

- `+`, `-`: requires both operands to have **identical** unit vectors. Output = either vector.
- `*`: output units = sum of exponent vectors (units multiply).
- `/`: output units = difference of exponent vectors.
- `sqrt`: valid only if all exponents are even (else result has fractional units like m^0.5). Output = halved exponents.
- `sq`: output = doubled exponents.
- `inv`: output = negated exponents (inverse units).
- `sin/cos/exp/log/…`: requires **dimensionless** argument (transcendental functions are only physically meaningful for dimensionless inputs). Output = dimensionless.

If `propagate_units` returns `None`, the operator is invalid for those operands and the tree builder tries another operator.

#### Affine Transformation (Kamienny et al. 2022)

After building an expression with variables `x1, x2, ...`, each variable is replaced by `aᵢ·xᵢ + bᵢ` (with `bᵢ = 0` for dimensioned variables to preserve units). This:
- Prevents the model from memorising a small library of exact canonical formulas
- Ensures it learns the underlying structural pattern (which factors multiply?) rather than the exact constants

#### Success Rate

Approximately 10% of sampled trees successfully pass all filters (unit consistency, non-constant, no NaN). This is expected — unit consistency is a strong constraint. The generator tries up to 50 times per equation.

#### Chunking for Memory Efficiency

To support large-scale pretraining (1M+ equations) without exhausting RAM, the dataset uses **incremental chunked saving**:

```python
generate_corpus(
    n_equations=1000000,
    cache_dir="cache/synthetic_1M",
    chunk_size=2000,  # Save every 2000 equations
    num_workers=4,
)
```

**How it works:**
1. Equations are generated in parallel across CPU workers
2. Every `chunk_size` equations, the batch is saved to `part_N.pt`
3. Memory is cleared after each save to prevent accumulation
4. A manifest file (`metadata_manifest.pt`) tracks all chunks for instant startup

**Output structure:**
```
cache/synthetic_1M/
├── metadata_manifest.pt    # Index of all chunks (for instant startup)
├── part_0.pt              # 2000 equations
├── part_1.pt              # 2000 equations
├── ...
└── part_499.pt            # 2000 equations (1M total)
```

#### LazySyntheticDataset — On-Demand Chunk Loading

For training, `LazySyntheticDataset` loads chunks on-demand rather than loading all data into RAM:

```python
dataset = LazySyntheticDataset(
    cache_dir="cache/synthetic_1M",
    max_cache_size=16,  # Keep max 16 chunks in memory
    n_rows=200,         # Subsample rows per equation
)
```

**Features:**
- **Thread-safe cache access:** Uses `threading.Lock` for multi-worker safety
- **LRU-style eviction:** Automatically removes oldest chunk when cache is full
- **Corruption handling:** Gracefully skips corrupted chunks and retries
- **Manifest-based startup:** Reads `metadata_manifest.pt` for instant indexing (no scanning)

**Memory usage:**
- Each chunk: ~1-2 MB (2000 equations)
- Max cache: 16 chunks × 2 MB = ~32 MB
- Far more efficient than loading 1M equations (~500 MB)

#### Multi-Worker DataLoader

The dataset is designed for parallel data loading on Colab and cloud instances:

```python
from torch.utils.data import DataLoader

loader = DataLoader(
    dataset,
    batch_size=128,
    num_workers=4,           # Colab: 4, Cloud: 8+
    persistent_workers=True, # Workers persist across epochs
    pin_memory=True,         # Linux-only (auto-detected)
    prefetch_factor=2,       # Each worker pre-fetches 2 batches
)
```

**Platform-aware configuration:**
- `pin_memory` is only enabled on Linux (Colab) for optimal performance
- `num_workers=4` is optimal for Colab's 2 vCPU cores (hyperthreading)
- `persistent_workers=True` reduces worker spawn overhead between epochs

**Why this works:**
| Workers | Throughput | Memory |
|---------|------------|--------|
| 0 (single) | ~100 samples/s | Low |
| 2 | ~300 samples/s | Medium |
| 4 (Colab default) | ~500 samples/s | ~40 MB |
| 8 (Cloud) | ~800 samples/s | ~80 MB |

## 2. Model Architecture

### 2.1 Embedders — `models/embedders.py`

#### `DataEmbedder`

**Input:** `X_bits [B, N, n_vars, 16]` — batch of N data points, each variable encoded as 16 bits.  
**Output:** `[B, N, n_vars, d_model]`

**Why per-bit embedding then sum?** Each bit carries a specific semantic meaning (sign, exponent magnitude, mantissa precision). A learned embedding per bit position allows the model to learn e.g. "bit 0 is the sign, so its embedding should encode polarity". Summing across 16 bits fuses them into one d_model vector per scalar value.

A variable-position embedding is added so the encoder knows which column (variable) each scalar belongs to.

#### `UnitEmbedder`

**Input:** `unit_idx [B, n_vars, 5]` — 5 class indices per variable (one per SI dimension).  
**Output:** `[B, n_vars, d_model]`

Each of the 5 dimensions has an independent embedding table of size 9 (exponents -4 to +4). The 5 embeddings are averaged into one `d_model` vector per variable. This gives the encoder physical identity information for each variable.

---

### 2.2 MixEncoder — `models/encoder.py`

**Role:** Process the `[B, N, n_vars, d_model]` data matrix and produce:
- `z_context [B, d_model]` — a single global summary of "what equation this data comes from"
- `var_summaries [B, n_vars, d_model]` — per-variable summaries used by the predictor

**Architecture:** Two stages, applied in sequence.

#### Stage 1: ISAB (Induced Self-Attention Block)

**Problem:** Standard self-attention over N data points costs O(N²). With N=1000 rows this is fine, but for pretraining with N=10,000+ it becomes infeasible.

**Solution:** Induced Self-Attention (Lee et al. 2019) — introduce M=32 learnable inducing points. Attention proceeds as:
1. `Attn(inducing_points → data)`: each inducing point attends to all N data points → `[M, d_model]`
2. `Attn(data → inducing_points)`: each of N data points now attends to just M inducing points → `[N, d_model]`

Complexity drops to O(N·M) which is linear in N. The inducing points act as a learned compression of the dataset into a fixed-size summary.

`n_isab=2` means two stacked ISAB blocks, increasing expressiveness.

#### Stage 2: Column Attention

After ISAB reduces the data to per-variable summaries, column attention allows variables to exchange information with each other. At this stage the model can learn patterns like "when variable 1 has force units and variable 2 has distance units, variable 3 is likely velocity".

`var_mask` is used to prevent padding slots from contributing to attention.

**Final pooling:** A learned mean-pool over variable slots produces the scalar `z_context [B, d_model]`.

---

### 2.3 Target Encoder — `models/target_encoder.py`

**Role:** Encode a ground-truth formula (as token IDs) into a representation `z_target [B, d_model]`.  
**Used only during training** — discarded at inference.

**Architecture:** Standard bidirectional Transformer encoder applied to token embeddings + unit embeddings (per-token unit vectors). A CLS-style pooling (mean over sequence length) gives the fixed-size `z_target`.

**Why does the target encoder see token unit embeddings and not just tokens?**  
The unit embedding at each token position encodes the *physical type* of that subexpression. The target encoder needs to understand "this formula produces velocity" — the unit of the output token is critical for the JEPA objective.

**Why is `z_target` not detached in the JEPA loss?**  
In the original I-JEPA (Image-JEPA), the target encoder is an EMA copy of the context encoder — gradients don't flow through it. Here, SIGReg replaces EMA. `z_target` receives gradients from `SIGReg(z_target)` only, not from `MSE(z_hat, z_target)`:
```python
L_jepa = MSE(z_hat, z_target.detach())  # target detached for MSE
L_sigreg = SIGReg(z_context) + SIGReg(z_target)  # z_target gets sigreg gradient
```

---

### 2.4 JEPA Predictor — `models/predictor.py`

**Role:** Predict `z_target` from `z_context` and `var_summaries`.  
**Used only during training.**

**Architecture:** Cross-attention where `z_context` is the query and `var_summaries` are keys/values. A bottleneck linear (ratio 0.5 → compresses to `d_model//2` → projects back) prevents the predictor from trivially copying its input.

**Why cross-attention rather than a simple MLP?**  
The predictor must "ask" the variable summaries for information that the global context might have compressed away. Cross-attention allows the predictor to selectively retrieve per-variable information. An MLP would treat `var_summaries` as a flat concatenation, losing the structure.

**Why a bottleneck?**  
The bottleneck forces the predictor to learn a compressed, abstract representation of the formula rather than memorising the path from context to target.

---

### 2.5 RPN Decoder — `models/decoder.py`

**Role:** Autoregressively generate an RPN formula from `z_context`.

**Architecture:** Standard causal Transformer decoder.
- Token embeddings + sinusoidal positional embeddings for each generated token
- `z_context` is projected and prepended as the first element of the key-value sequence (cross-attention memory)
- Unit embeddings (for the input variable slots) are also part of the cross-attention memory so the decoder can attend to "what units does variable 1 have?"

**Teacher forcing during training:**  
Input: `[BOS, t1, t2, ..., t_{T-2}]`  
Target: `[t1, t2, ..., t_{T-2}, EOS]`  
The model sees the correct previous token at every step. This is standard seq2seq training.

**Causal mask:**  
A lower-triangular mask prevents token `t` from attending to future tokens. At inference, generation is truly sequential with no teacher forcing.

#### `UnitPredictionHead`

A shared linear layer that projects each decoder hidden state to 5 × 9 logits — one 9-class classifier per SI dimension. This trains the decoder's internal representations to be aware of dimensional analysis, acting as an inductive bias towards physically consistent outputs.

---

### 2.6 Full Model — `models/model.py`

**`LLMJEPA.forward()`** is the training pass:

```python
z_context, var_summaries = encode(X_bits, unit_idx, var_mask)
z_target  = target_encoder(token_ids, unit_idx)         # formula → representation
z_hat     = predictor(z_context, var_summaries, var_mask) # predict formula repr
logits, h_states = decoder(token_ids[:,:-1], z_context, unit_idx) # teacher-forced
```

**Inference-time simplification:** Only `DataEmbedder + UnitEmbedder + MixEncoder + RPNDecoder` are needed — roughly half the parameters. The `TargetEncoder` and `JEPAPredictor` are loaded from the checkpoint but not called.

## 3. Training

### 3.1 Loss Functions — `training/losses.py`

Four loss terms combined with configurable weights:

```
L_total = λ_jepa · L_jepa  +  λ_sigreg · L_sigreg  +  λ_lm · L_lm  +  λ_units · L_units
```

All four default to weight 1.0.

#### `SIGRegLoss` — Sketched Isotropic Gaussian Regularisation

**Problem:** In JEPA, both encoders need to be prevented from collapsing to a trivial constant representation. Original I-JEPA uses EMA (a slowly-moving copy of the context encoder as the target encoder). EMA is effective but adds a momentum hyperparameter and prevents gradients from flowing through the target.

**SIGReg solution (LeJEPA, Dieuleveut et al. 2024):** Constrain both `z_context` and `z_target` to follow an isotropic Gaussian distribution. Collapse is impossible for a Gaussian — it has nonzero variance by definition.

**How:** A statistical test (Sliced Univariate Test via Epps-Pulley statistic) checks whether the batch of embeddings could have come from a standard normal. The test statistic is the loss — it's 0 only for a perfect standard normal, higher for any deviation.

**Slicing:** The full `d_model`-dimensional distribution is tested via M random 1D projections (slices). Each slice reduces the multivariate problem to a univariate one. `num_slices=512` gives a good balance of test power vs. speed.

**Why this isn't just variance loss:** VICReg and similar methods add variance terms to prevent collapse but don't ensure the *covariance structure* is isotropic. SIGReg tests the full distribution, catching both variance collapse and directional correlations.

#### `JEPALoss` — MSE Prediction Loss

```python
L_jepa = F.mse_loss(z_hat, z_target.detach())
```

`z_target.detach()` is critical: gradients from the MSE loss only flow through `z_hat` (thus through the predictor and context encoder). If `z_target` received the MSE gradient, both encoders would converge to the same point, which is the degenerate solution the JEPA objective tries to avoid. SIGReg handles regularising `z_target` separately.

#### `ValidityWeightedCE` — LM Loss with RPN Grammar Penalty

Standard cross-entropy loss over the vocabulary at each decoder position, but with a twist: tokens that violate RPN grammar at their position receive increased weight (`invalid_weight=2.0`).

**How grammar is checked at scale:** Rather than running a Python loop per sequence, the validity is computed fully vectorised:

1. Map each input token to its stack-depth delta via `arity_map[token_ids]` (lookup table)
2. Compute cumulative sum of deltas → stack depth at each position for the whole batch in one `torch.cumsum` call
3. Use the depths to check validity conditions for every `(batch, timestep)` simultaneously via boolean masks

This avoids Python loops and runs as a single GPU kernel.

**Why penalise invalid tokens more, rather than masking them to 0?**  
Hard masking (setting probability to 0) is done during *inference* via `get_valid_next_tokens`. During *training*, hard masking would mean the model receives no gradient signal for invalid tokens. Soft up-weighting still penalises them but lets gradients flow, helping the model learn the grammar more aggressively.

#### `UnitLoss` — Dimensional Analysis Auxiliary Loss

For each of the 5 SI dimensions, the decoder hidden states are classified against the ground-truth unit exponent for that token position. Mean cross-entropy across 5 dimensions.

This loss trains the decoder's internal representations to track dimensional analysis, acting as a strong inductive bias: the model can't just predict chemically valid but physically nonsensical formulas.

**`ignore_index=-100`:** PAD positions have their unit targets set to -100, which `F.cross_entropy` automatically ignores.

### 3.2 Lightning Module — `training/trainer.py`

**`LLMJEPAModule`** wraps `LLMJEPA + LLMJEPALoss` as a PyTorch Lightning module.

#### Optimizer: AdamW with Cosine Warmup

```python
optimizer = AdamW(lr=1e-3, weight_decay=1e-2, betas=(0.9, 0.95))
scheduler = LambdaLR(lr_lambda=_lr_lambda, interval='step')
```

**Linear warmup:** First `warmup_steps` (default 500) steps linearly ramp up from 0 → lr. This prevents early instability when the model's gradients are large and poorly conditioned.

**Cosine decay:** After warmup, the learning rate follows a cosine curve from lr → 0 over the training horizon. This has been empirically shown to work better than constant lr because it decays more aggressively early (large steps when far from optimum) and more gently late (fine adjustments).

`betas=(0.9, 0.95)` follows GPT-style training — the second momentum coefficient is lower than the standard 0.999, giving faster adaptation but less noise smoothing.

#### Gradient Clipping

`gradient_clip_val=1.0` in the Trainer. Clips the global gradient norm to 1.0. This prevents any individual gradient explosion from dominating the update — critical for transformers which can produce large attention gradients in early training.

#### TensorBoard Logging

All four loss components are logged at both step and epoch granularity:
```python
self.log('train/total', loss, on_step=True, on_epoch=True, prog_bar=True)
self.log('train/jepa', ...)
self.log('train/sigreg', ...)
self.log('train/lm', ...)
self.log('train/units', ...)
```

`detach()` is called on individual components before logging to prevent keeping gradient computation graphs in memory.

### 3.3 Training Entry Point — `training/train.py`

**YAML-driven configuration:** All hyperparameters are centralised in a YAML config file. Changing a single value (e.g. `d_model`) automatically propagates to the model, optimizer, and dataset.

**Auto train/val split (90/10):**  
```python
val_size = max(1, int(0.1 * len(full_dataset)))
train_dataset, val_dataset = random_split(full_dataset, [train_size, val_size],
                                          generator=torch.Generator().manual_seed(42))
```
`manual_seed(42)` ensures the split is reproducible across runs — same equations are always in train vs. val.

**Two data modes:**
- `use_synthetic: true` — pretraining on generated physics equations (unlimited data, controlled complexity)
- `use_synthetic: false` — fine-tuning/evaluation on the AIF Feynman dataset (real physics, bounded to 100 equations)

## 4. Inference

### `inference/generate.py` — `InferenceModel`

**Inference-only model** that loads only the four components needed at test time:
`DataEmbedder + UnitEmbedder + MixEncoder + RPNDecoder`

The `TargetEncoder` and `JEPAPredictor` — which together represent ~half the parameters — are not used. They are loaded from the checkpoint but not called.

#### `generate()` — Autoregressive Decoding with Validity Masking

```
Initialize: sequence = [BOS], stack_depth = 0, finished = [False, ..., False]

For each step:
    logits = decoder(sequence, z_context, unit_idx)   # [B, vocab_size]

    Build validity mask [B, vocab_size]:
        for each sequence b:
            valid_tokens = get_valid_next_tokens(stack_depth[b], step, max_len)
            mask[b, valid_tokens] = 0.0  (allow)
            mask[b, others]       = -inf  (block)

    next_token = argmax(logits + mask)    # greedy
    or
    next_token = sample(softmax((logits + mask) / temperature))  # sample

    Update stack_depths using arity_map lookup (vectorized)
    Mark sequences as finished if next_token == EOS

    If all finished: break
```

**Vectorized stack update:**
```python
arity_map = {leaf: +1, unary: 0, binary: -1}
deltas = arity_map[next_tokens]  # [B] lookup
stack_depths = clamp(stack_depths + deltas, min=0)
```
This runs the stack depth update for the whole batch in a single tensor operation.

**The validity mask is the key difference between this and a standard LM decoder.** Without it, the model can generate syntactically invalid RPN (e.g. a binary operator when the stack has only one element). With it, every generated sequence is guaranteed to be a valid RPN expression.

### `inference/beam_search.py` — ODEFormer Pipeline

**ODEFormer-style inference** replaces greedy decoding with diversity-focused sampling and ranking.

#### Pipeline Steps

```
1. Encode: z_context = model.encode(X_bits, unit_idx, var_mask)

2. Diversity Pool Sampling:
   - Generate N candidates using temperature-controlled sampling
   - Batch generation for efficiency

3. Skeleton Deduplication:
   - skeletonize(): Replace c1,c2,... and numeric literals with CONST placeholders
   - Keep only unique skeletons (SymPy-based structural comparison)

4. BFGS Optimization (per unique skeleton):
   - Replace CONST placeholders with C1, C2, ... (SymPy symbols)
   - Define MSE objective: L(c) = mean((y_true - f(x; c))^2)
   - Minimize using L-BFGS-B (max_iter=100, n_restarts=5)
   - Score by R² on FULL dataset

5. Ranking:
   - Sort candidates by R² (descending)
   - Return top-k candidates
```

#### `skeletonize()` — Structural Deduplication

```python
def skeletonize(token_ids: List[int]) -> Optional[str]:
    # 1. Convert RPN → SymPy expression
    expr = rpn_to_sympy(token_ids)
    
    # 2. Replace c1, c2, ... with CONST0, CONST1, ...
    for i, cp in enumerate(const_placeholders):
        expr = expr.subs(cp, sympy.Symbol(f'CONST{i}'))
    
    # 3. Replace numeric literals with CONST_NUM0, CONST_NUM1, ...
    for i, atom in enumerate(expr.atoms(sympy.Number)):
        expr = expr.subs(atom, sympy.Symbol(f'CONST_NUM{i}'))
    
    # 4. Return canonical string representation
    return str(sympy.simplify(expr))
```

**Why unique placeholders?** Using `CONST0`, `CONST1`, etc. (instead of a single `CONST`) preserves structural distinctions. For example, `c1*x1 + c2` becomes `CONST0*x1 + CONST1` (not `CONST*x1 + CONST` which would incorrectly simplify to `CONST*(x1 + 1)`).

#### `fit_and_score()` — BFGS Constant Recovery

```python
def fit_and_score(skeleton_str, tokens, X, y_true, var_names, max_iter=100, n_restarts=5):
    # 1. Parse skeleton and replace CONST{i} with C1, C2, ...
    final_expr = ...  # e.g., C1*x1 + C2
    
    # 2. Create lambdified function ONCE (numerical stability)
    f_lambdified = sympy.lambdify([x1, C1, C2], final_expr, 'numpy')
    
    # 3. Define MSE objective
    def objective(params):
        y_p = f_lambdified(X.T, *params)
        return mean((y_true - y_p)**2)
    
    # 4. Multi-restart BFGS with diverse initializations
    for restart in range(n_restarts):
        x0 = diverse_initialization(restart)  # [1s, 0.1s, random...]
        res = minimize(objective, x0, method='L-BFGS-B', options={'maxiter': max_iter//n_restarts})
        track_best_result()
    
    # 5. Return optimized expression and R²
    return {'expression': str(optimized_expr), 'r2': r2, 'fitted_params': best_params}
```

**Key optimizations:**
- **Lambdify once:** Creating the lambdified function outside the objective prevents numerical instability
- **Multi-restart:** 5 diverse initializations (ones, small values, random ranges) escape local minima
- **Iteration budget:** 100 total iterations (20 per restart) balances speed and accuracy
- **Parallel execution:** Skeletons are fitted in parallel across CPU workers (default: 8)

## 5. Evaluation

### Goldilocks Evaluation Suite

The evaluation pipeline uses three core "Goldilocks" metrics that provide a complete picture of model performance:

1. **Numeric Precision (R²)** - Quality of fit on original data
2. **Symbolic Accuracy (SA)** - Functional equivalence via random point evaluation  
3. **Normalized Edit Distance (NED)** - Structural similarity via prefix trees

### `evaluation/metrics.py`

#### R² Score (Coefficient of Determination)

```python
def calculate_r2(y_true: np.ndarray, y_pred: np.ndarray) -> float:
    """
    R² = 1 - SS_res / SS_tot
    
    Returns:
        1.0 for perfect fit
        0.0 for prediction = mean(y_true)
        -inf for degenerate predictions
    """
```

**Interpretation:**
- R² = 1.0: Perfect fit
- R² = 0.0: Prediction is no better than predicting the mean
- R² < 0: Prediction is worse than the mean (model is broken)

#### Symbolic Accuracy (Functional Equivalence)

```python
def verify_symbolic_accuracy(
    pred_expr_str: str,
    true_expr_str: str,
    var_names: List[str],
    n_points: int = 1000,
    tol: float = 1e-5
) -> bool:
    """
    Check functional equivalence via random point evaluation.
    More robust than algebraic simplification for complex forms.
    """
```

**Algorithm:**
1. Try algebraic simplification: `simplify(pred - true) == 0`
2. If that fails, evaluate both expressions on 1000 random points in [0.1, 5.0]
3. Return True if `allclose(pred, true, atol=tol, rtol=tol)`

**Why random point evaluation?** Algebraic simplification can fail for complex equivalent forms (e.g., `sin²x + cos²x` vs `1`). Numerical evaluation on random points is more robust.

#### Normalized Edit Distance (NED)

```python
def calculate_ned(pred_expr_str: str, true_expr_str: str) -> float:
    """
    Convert expressions to prefix notation trees and compute Normalized Edit Distance.
    
    Returns:
        0.0 for identical trees
        1.0 for completely different trees
    """
```

**Algorithm:**
1. Parse both expressions to SymPy
2. Serialize to prefix notation: `x1 + x2` → `['Add', 'x1', 'x2']`
3. Compute SequenceMatcher ratio
4. Return `1.0 - ratio`

**Interpretation:**
- NED = 0.0: Identical structure
- NED = 0.1-0.3: Minor structural differences (e.g., commutative reordering)
- NED > 0.5: Major structural differences

#### Constant Recovery

```python
def calculate_constant_recovery(
    pred_consts: List[float],
    true_consts: List[float],
    tol: float = 0.1
) -> float:
    """
    Measure how well fitted constants match ground truth.
    
    Returns:
        1.0 if all constants within tol relative error
        0.0 if any constant is wrong or length mismatch
    """
```

**Note:** Only meaningful when Symbolic Accuracy = True (correct skeleton).

def evaluate_dataset(model, dataset, device, n_candidates=50, temperature=0.1) -> Dict:

### 5.1 Metrics — `evaluation/metrics.py`

#### `calculate_r2(y_true, y_pred)`
Coefficient of determination: `R² = 1 - SS_res / SS_tot`. Returns 1.0 for perfect prediction. This is the primary metric for the "Goldilocks" search.

#### `calculate_ned(predicted_str, ground_truth_str)`
**Normalized Edit Distance**: Measures the structural similarity between the predicted RPN sequence and the ground truth. Useful for tracking how close the model is to the true structure even if numerical constants are off.

#### `calculate_sa(predicted_expr, ground_truth_expr)`
**Symbolic Agreement**: Binary metric that checks if the predicted formula is symbolically equivalent to the ground truth using `sympy.simplify`. Includes a numerical fallback for complex cases (evaluating at 10 random points).

#### `fit_constants_with_scipy(expr, X, y, var_names)`
**Input:** A SymPy expression containing `c1`..`c5` placeholders.  
**Output:** Minimized MSE and the optimized SymPy expression.

**Algorithm:**
1. Compiles the expression to a fast NumPy function using `sympy.lambdify`.
2. Defines an MSE objective function for SciPy's `minimize` routine.
3. Uses the **BFGS** method to find optimal constant values.
4. Returns the finalized expression with decimal constants substituted back in.

### 5.3 Stress Tests

**Noise tolerance** (`_test_noise_tolerance`): Add Gaussian noise `ε ~ {0.001, 0.01, 0.1}` × std(y) to the target. Refit constants on noisy data, report R². Tests robustness to measurement error.

**Data efficiency** (`_test_data_efficiency`): Subsample `N ∈ {10, 50, 100, 200}` data points. Generate formula from the subsampled context, fit constants on subsampled data, evaluate on the full dataset. Tests how much data the model needs.

**OOD Extrapolation** (`_test_extrapolation`): Sample data from 10× outside the original variable ranges. Evaluate the fitted formula there. Tests whether the model discovers the true symbolic form (which extrapolates correctly by definition) vs. a numerical approximation (which won't extrapolate).
